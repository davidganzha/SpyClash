# Restore verified transactions before forced App Store authentication — build 159

## Observed failure

On iOS 26.4.2 with TestFlight 1.0.2 (158), Restore failed after Apple authentication.
The captured device Console sequence on 2026-09-19 was:

- 19:05:29.566778 +0200, `appstored`: successful authentication; the returned
  sandbox account was not active or selected.
- 19:05:29.567363, `storekitd`: `No active account for transaction history request`.
- 19:05:29.567389, `storekitd`: `Error syncing transactions: accountMissing`.
- 19:05:29.573528, SpyClash: `IAP-RESTORE-APPLE-NONE: STOREKIT_UNKNOWN`.

No account identifiers, credentials or raw transaction data are retained here.
After restarting the phone, the user reported the same Restore failure. Apple's
Manage Subscriptions sheet showed an existing Sandbox subscription with renewal
cancelled and access expiring on September 20; cancellation of renewal is not
immediate expiration.

## Change

Restore first reconciles transactions already provided by StoreKit. The existing
signature verification and server-side current subscription-status verification
remain mandatory. A positive active-transaction count is followed by a fresh
membership refresh and active-access check before reporting success.

Only when no active verified purchase is found does Restore call `AppStore.sync()`
and then read transactions again. Sync failures remain failures, cancellation stays
cancelled, and an active membership snapshot alone cannot produce Restore success.
Account-generation and foreground/background operation guards remain in place.

StoreKit's known `unsupported` case is now reported separately from `unknown`;
unrecognized future cases no longer collapse into the same support code.

This follows Apple's guidance that StoreKit normally supplies transaction history
without forcing authentication:
https://developer.apple.com/documentation/storekit/appstore/sync()

## Verification

- Membership and StoreKit catalog suites: **60 passed, 0 failed, 0 skipped**.
- Nine new regression tests cover available purchases with a failing forced-sync
  implementation, missing-purchase sync/recheck, empty history, sync failure,
  unavailable/revoked/expired membership, verification and delivery failures,
  account switching, concurrent Restore, and distinct StoreKit diagnostics.
- Existing cancellation and foreground/background ownership tests were updated
  for the initial transaction-history read.
- Marketing version remains 1.0.2; build number is synchronized at 159.

## Remaining acceptance

This change does not repair Apple's account activation or prove that this phone
currently exposes a usable StoreKit transaction. If none is available, forced sync
may still return `accountMissing`; it must remain visible rather than being called
a successful restore. Real purchase/Restore verification on the new TestFlight
build is required. TestFlight upload and public release require fresh approval.
No backend or Apple account configuration was changed.
